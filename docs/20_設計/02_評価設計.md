## 1. なぜ評価設計を先に書くのか

- 加点観点の「技術力」「実用性」は、**数値がないと主張できない**。
- 実装の後に評価を考えると、**都合のよい条件を後から選ぶ**ことになり、結果の信頼性が落ちる。
- **実装前に「何を、何回、どう測るか」を固定する。**

---

## 2. 測る指標

| ID | 指標 | 定義 | 目的 |
|---|---|---|---|
| **M-1** | タスク成功率 | 指示された全手順を完遂したエピソード数 ÷ 総エピソード数 | 主指標 |
| **M-2** | 手順成功率 | 成功した手順数 ÷ 総手順数 | どこで落ちるかを見る |
| **M-3** | 対象同定の正解率 | 知覚層が正しい物体を指した手順数 ÷ 総手順数 | **AIの寄与**を直接測る |
| **M-4** | サイクルタイム | 1手順あたりの所要**実時間**（秒。`time.perf_counter` の壁時計） | 実用性の主張に使う |
| **M-5** | 失敗モード内訳 | §3 の分類ごとの件数 | 実用性・改善余地の説明 |

> **報告時は必ず「分子／分母」の形で書く**（例: 12/20 = 60%）。
> 率だけを書くと母数が消え、後から比較できなくなる。
> `src/eval.py` は `step_success_fraction` など**分数形式を必ず出力**する。

## 3. 失敗モードの分類（相互排他・網羅）

失敗したエピソードは、**最初に発生した事象**で1つだけに分類する。

| コード | 名称 | 定義 |
|---|---|---|
| F-1 | 計画失敗 | 指示文から妥当な手順が生成されなかった |
| F-2 | 対象取り違え | 別の物体を対象として選んだ |
| F-3 | 未検出 | 対象が画面内にあるのに検出できなかった |
| F-4 | 位置誤差 | 検出はしたが、3D位置がずれて届かなかった |
| F-5 | 把持失敗 | 掴もうとしたが保持できなかった（落下含む） |
| F-6 | 搬送失敗 | 運搬中に落とした・他の物体に衝突した |
| F-7 | 配置失敗 | 目的地の外に置いた |
| F-8 | タイムアウト | 制限ステップ内に完了しなかった |
| F-9 | その他 | 上記に当てはまらない（**個別に記述を残す**） |

> **検算を必ず行う**: `成功数 + Σ(F-1..F-9) == 総エピソード数`。
> 過去に内訳の1バケツを書き落とし、合計が母数と合わない報告を出した事例がある。
> **`src/eval.py` がこの等式を自動検査し、合わなければ `LedgerMismatch` 例外で止める（実装済み）。**
> 未定義の失敗モードが現れた場合も同じく止める。

## 4. 実験条件（アブレーション）

**AIが効いていることを示す**ための比較。同一のシーン・同一の乱数種で対にする。

| 条件 | 計画層 | 知覚層（位置） | 把持姿勢の向き | 目的 |
|---|---|---|---|---|
| **C0** 基準 | 固定ルール | 真値 | 真値 | 制御層の上限性能。ここが低いと他の議論ができない |
| **C0'** | 固定ルール | 真値 | 固定 | 向き合わせだけの寄与 |
| **C1** | 固定ルール | モデル（視線交点） | 真値 | 知覚AIの位置の寄与 |
| **C1d** | 固定ルール | モデル（深度読取） | 真値 | 位置の求め方の寄与 |
| **C2** | 固定ルール | モデル（視線交点） | 固定 | 向きの情報を失ったとき |
| **C3** 知覚・姿勢がAI | 固定ルール | モデル（視線交点） | **モデル（上面の矩形）** | **知覚系が真値を一切使わないときの実力** |
| **C4** 全層AI | 言語モデル | モデル | モデル | 提案手法の最終形（**実装済み・提出構成**） |

> **真値を一切使わないのは C3 と C4。** C4 は計画層まで言語モデルにした**提出構成**である
> （C3 との差はゼロ＝言語計画層のコストがゼロ、が主張。実測は exp003）。
> 報告で C1 の数値を使うときは、**向きに真値を使っていることを必ず明記する**。

### 4.1 比較の作法（過去の失敗から）

| # | 守ること | 理由 |
|:-:|---|---|
| 1 | **条件間で乱数種と初期配置を揃える** | 揃えないと差が初期条件の運で消える |
| 2 | **少ない試行数の±1〜2の差を解釈しない** | 8試行で 4/8 と 3/8 が同一条件で出た実測がある |
| 3 | **1条件だけ設定を変えて比較する** | 2つ同時に変えるとどちらが効いたか分からない |
| 4 | **「差が出なかった」を「同等」と書かない** | 非有意は同等性の証明ではない |
| 5 | **単体試行の成功率を連続タスクに外挿しない** | **実測で Can が単体 5/5 → 連続 5/10 に落ちた**（[L1結果 §5-1](../30_評価/20260927_L1ベースライン_結果.md)） |
| 6 | **推定器を作ったら必ず「当てずっぽう」と比べる** | **実測で、向き推定の初版は誤差中央値 25.3度で、ランダム（23.2度）より悪かった**。基準線が無ければ「まあまあ使える」として採用していた |
| 7 | **取り得る誤差の範囲を先に知る** | 角度の誤差は対称性を畳むと**最大45度**にしかならない。範囲を知らないと 25度を「半分当たっている」と誤読する |
| 8 | **差が出たら、まず「何が違っているか」を全部並べる** | C4 が C3 より12手順低かったが、**計画の中身は同一で順番だけが違った**。交絡を切り分けなければ「言語モデルが劣る」という**誤った結論**を書いていた |
| 9 | **評価に使う入力を few-shot の例に入れない** | 答えを見せてから同じ問題を出すことになり、測れるのは汎化でなく**書き写せるか**になる |

## 5. 試行数（**実測をもとに確定**）

| 項目 | 値 | 根拠 |
|---|---|---|
| 1エピソードの手順数 | 3（Milk / Can / Bread） | タスク定義 |
| 1エピソードの所要時間 | **実測 約8.4秒**（約630ステップ、サイクル 2.80秒/手順） | [L1結果](../30_評価/20260927_L1ベースライン_結果.md) |
| **1条件あたりのエピソード数** | **20** | 20エピソード ≈ 3分。十分に回せる |
| 条件数 | 7（C0 / C0' / C1 / C1d / C2 / C3 / C4） | §4 |
| 総計 | **140 エピソード ≈ 21分**（知覚推論込みではさらに増える） | — |

> **試行数は実装前に決め、結果を見てから増減しない。** 都合のよい試行数を後から選ぶと結果が信用できなくなる。
> **2026-09-27 の L1 ベースラインは 10 エピソードで採った**が、これは成否を見るためのスパイクであり、
> **条件間の比較には使わない**。比較は 20 エピソードで取り直す。

## 6. 「AIが本当に効いているか」の決定的テスト

数値の比較とは別に、**配管が繋がっていることを直接確かめる**。

| テスト | 手順 | 期待される結果 |
|---|---|---|
| T-1 画像遮断 | 入力画像をすべて 0 にして知覚層を呼ぶ | 検出が消える／結果が明確に変わる。**変わらなければ画像が使われていない** |
| T-2 語の入れ替え | 探す語を「りんご」→「ドライバー」に変える | 検出される物体が変わる。**変わらなければ言語が使われていない** |
| T-3 出力の固定確認 | 異なる入力に対する出力を比較 | 常に同じ値なら、モデルが壊れているか配線ミス |

> **これは過去に実害が出た型である。** 学習済み重みが壊れており、どの入力でも同じ出力を返していたのに
> 気づかず時間を溶かした事例がある。**モデルを導入した最初の日に T-1〜T-3 を通す。**

## 8. リークと公平性

本課題は学習を行わない方針（DEC-07）のため、学習データと評価データの重複問題は発生しない。
ただし**学習を行う方針に変更した場合は、以下を必須とする**。

- 評価に使うシーン・物体配置を、学習に使ったものと**明示的に分ける**。
- 分割は物体インスタンス単位ではなく、**シーン（またはシード群）単位**で切る。
- 「重なり0件」は、**比べていないときにも0件になる**。検査は「比べる相手が存在すること」も確認する。
