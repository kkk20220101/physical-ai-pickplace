# 公開リポジトリの組み立てと提出経路の実証（I-A 予行 / I-B）

**実施日**: 2026-09-28
**目的**: **本人判断（U-02 / U-08）が届いた瞬間に「1コマンドで終わる」状態**まで進める。
**結論**:
- **提出パッケージは、アカウント名さえ入れれば NG 0件になることを実証した**（予行で確認）。
- **公開リポジトリはローカルに組み上がった**（commit 済み。ファイル数は§4-2）。**push だけが残っている。**
- **その過程で、公開検査に 3つの欠陥が見つかり、3つとも塞いだ。**
  うち1件は **禁止語の一覧そのものを公開リポジトリへ載せる**という実害のある欠陥だった。

---

## 1. 調査結果 — 公開検査に見つかった3つの欠陥

**いずれも「検査は通っていたのに、見ていなかった」型**である（リスク R-24 と同型）。

| # | 欠陥 | どう発覚したか | 実害 |
|:-:|---|---|---|
| **1** | **許可済みフォルダに新規文書を置くと、既定で公開される** | 上司向け進捗報告を `docs/40_報告/` に作った直後、公開対象が **70→71** に増えた | 社内向けの進捗報告が公開されるところだった |
| **2** | **公開文書から社内限り文書へのリンクが死ぬ** | リンク検査を足したら **3ファイル4箇所**が即座に該当 | 公開リポジトリのリンク切れ。読者が辿れない |
| **3** | **禁止語検査器そのものが公開対象だった** | 複製後の再走査が `scripts/check_publish_safety.py:34` を該当として検出 | **禁止語の一覧（業務案件名・組織名）を公開リポジトリに載せる**。最も重い |

### 欠陥3 がなぜ長く見えなかったか

検査器は `SELF = "scripts/check_publish_safety.py"` で**自分自身を走査対象から外していた**。
これは「自分の出力を自分で検出する」問題（DEC-31）への対処だったが、
**同時に「唯一、禁止語を全部書いてあるファイル」を検査の外へ出してしまった**。

> **運用ルール**: **検査対象から外したものは、公開対象からも外す。**
> 「見ないことにした」と「出してよい」は別である。
> **今回は `SELF` を廃止し、allow-list 側の除外に一本化した**（下記 DEC-34）。
> これにより、誤って公開対象へ戻したときは**検査が自分を検出して止まる**＝安全側へ倒れる。

## 2. 意思決定

| ID | 決めたこと | 理由 |
|---|---|---|
| **DEC-33** | **公開リポジトリは作業ツリーで `git init` せず、別ディレクトリへ複製して組む** | 作業ツリーには社内限り文書が同居する。`git add` を一度誤ると**履歴に残って取り消せない**。**出せないものは「除外し忘れる」のでなく、そもそもそこに置かない** |
| **DEC-34** | **allow-list に除外行（`!`）を導入する** | 許可はフォルダ粒度になりがちで、**許可済みフォルダの中の1ファイルだけ出さない**という要求が実際に生じた（欠陥3）。順序規則は `.gitignore` と同じ＝後の行が勝つ |
| **DEC-35** | **公開文書は社内限り文書へリンクしない。本文にファイル名と「社内限り」と書く** | 公開側でリンクが切れる。**公開時にリンクを書き換える方式は採らない**——作業ツリーと公開物で本文が変わると、どちらが正か分からなくなる |
| **DEC-36** | **社内向けの進捗報告は `tasks/` に置く**（`docs/40_報告/` に置かない） | `docs/40_報告/` は**提出物の原稿置き場で公開対象**。進捗報告は提出物ではない。置き場で公開可否が決まる以上、**種類でフォルダを分けるのが唯一の守り方** |

## 3. 実装

| ファイル | 変更 |
|---|---|
| `scripts/build_public_repo.py` | **新規**。allow-list ∩ `.gitignore` を別ディレクトリへ複製 → 再走査 → `git init`／`commit`。**push はしない** |
| `scripts/check_publish_safety.py` | **リンク検査を追加**（公開文書が公開対象外を指していないか）。**allow-list に `!` 除外を追加**。**`SELF` 例外を廃止** |
| `configs/publish_manifest.txt` | `!scripts/check_publish_safety.py` を追加 |
| `docs/20_設計/01_システム設計.md` ほか3件 | 社内限り文書へのリンクを平文へ（DEC-35） |
| `tasks/04_進捗報告_上司向け_20260928.md` | `docs/40_報告/` から移設（DEC-36） |

### 3-1. `build_public_repo.py` が守っていること

1. **`check_publish_safety.py` が「公開可」でなければ組み立てない**（戻り値で判定）
2. 複製後に**置かれた実物をもう一度走査する**（一覧を信じない）
3. **複製数と `git ls-files` の数が一致しなければ失敗**（公開側の `.gitignore` に食われていないか）
4. `README_public.md` → `README.md` に改名（GitHub の入口）
5. **push しない。**コマンドを表示して止まる

> **「一覧が正しいこと」と「置かれた物が正しいこと」は別の検査である。**
> 実際、欠陥3 は**一覧の検査では 0件**だったのに**複製後の再走査で出た**。
