## 仮説（実験前に書いた）

小型の言語モデル（1.5B〜3B）に指示文を渡せば、
`[{"target": ..., "destination": ...}]` の手順を安定して出せる。
**大きいモデルのほうが正確だろう。**

## 条件

| 項目 | 値 |
|---|---|
| 候補モデル | Qwen2.5-1.5B-Instruct（3.1GB）／ Qwen2.5-3B-Instruct（6.2GB） |
| 繰り返し | 基本指示を10回 |
| 言い換え | 4種（固定ルールでは**1つも扱えない**文） |
| 妨害物 | シリアルの箱を選んだら失敗として数える |
| 決定的テスト | 空文字・無関係な文を与えて**手順を出さない**こと（3種） |
| 生成 | 貪欲法（temperature=0）。JSON にならなければ最大2回作り直す |

## 経過

### 第1段: 評価の作り方が間違っていた

最初の system prompt の例が、**評価に使う基本指示そのもの**だった。

```
例:
指示「飲み物を左の箱へ、食べ物を右の箱へ」   ← 評価で使う文と同一
出力 [{"target": "牛乳パック", ...}, ...]
```

> **これは答えを見せてから同じ問題を出しているのと同じ**であり、
> 測っているのは汎化ではなく**書き写せるか**になる。
> ∴ 例を別の指示（「シリアルとパンを右の箱へ」）に差し替えてから測り直した。

### 第2段: 例を差し替えて測る → 両モデルとも**1つ落とす**

| モデル | JSON | 期待どおり | 言い換え | 妨害物除外 | 決定的 |
|---|:-:|:-:|:-:|:-:|:-:|
| 1.5B | 10/10 | **0/10** | 2/4 | 10/10 | 3/3 |
| 3B | 10/10 | **0/10** | 3/4 | 10/10 | 3/3 |

基本指示（3手順が正解）に対し、**1.5B は牛乳を落とし、3B はパンを落とす**。
いずれも**ちょうど1つ足りない**。

> **「モデルが弱いから」で片付けず、落ち方の形を見た。**
> 常に1つ足りないのは能力の問題というより**出力の長さの問題**に見える。
> このとき system prompt の例は**1要素だけ**だった。

### 第3段: 例を2要素にする（**これだけ**変える）

| モデル | JSON | 期待どおり | 言い換え | 妨害物除外 | 決定的 |
|---|:-:|:-:|:-:|:-:|:-:|
| **1.5B** | 10/10 | **10/10** | **4/4** | 10/10 | 3/3 |
| 3B | 10/10 | 0/10 | 3/4 | 10/10 | 3/3 |

**1.5B は 0/10 → 10/10 になった。** 変えたのは例の要素数だけである。

## 結論

**仮説は前半が正しく、後半が外れた。**

1. **正しかった**: 小型モデルで手順の JSON を安定して出せる（パース 10/10）。
2. **外れた**: **大きいモデルのほうが良いとは限らなかった。**
   3B は例を2要素にしても 0/10 のままで、1.5B に負けた。
3. **予想していなかったこと**: **例の要素数が、モデルの大きさより効いた。**
   1要素の例を見せると、モデルは1〜2要素しか出さなくなる。

## 採用

**Qwen2.5-1.5B-Instruct ＋ 2要素の例** を採用（DEC-22）。
判断基準（パース ≥9/10・言い換え ≥3/4・妨害物除外）をすべて満たす。
**より小さく・より速く・より正確**という珍しい組み合わせになった。

## 言えないこと

- 10回はすべて貪欲法（temperature=0）なので**同じ出力**になる。
  これは「安定して同じものを出す」ことの確認であって、**多様な入力への頑健性ではない**。
- 言い換え4種での 4/4 と 3/4 の差は**4件での比較**であり、モデルの優劣を結論づける数ではない。
- 3B が劣った理由は**切り分けていない**（例の形との相互作用の可能性がある）。
- 日本語の指示に限った結果。
